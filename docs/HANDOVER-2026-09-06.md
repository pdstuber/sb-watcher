## 1. Orientation: what this project is

`sb-watcher` polls one sold-out SUMMER BREEZE 2027 ticket page every 60 seconds, watching the
resale exchange ("Ticketbörse"), and alerts the owner over Telegram plus an optional ntfy channel.
It runs 24/7 on fly.io as the app `sb-watcher`. The owner needs two tickets. Returned tickets sell
within minutes and can appear at any hour.

**The one thing that matters:** this program must never fail silently. A watcher that is broken
but looks healthy is worse than one that crashes, because the owner will not know to check. Almost
every design decision in the repo follows from that, and so does every fix on this branch.

`CLAUDE.md` at the repo root is the authoritative guide. It lists invariants that must not be
broken. Read it. Highlights that trip people up:

- **Detection is inverted, deliberately.** The resale state is `Empty` if and only if the card
  text contains the German empty-state sentence. **Anything else is `Available`.** Never add a
  positive pattern that gates the alert: a positive matcher fails closed, so unfamiliar markup
  would read as "all quiet" and the drop would be missed. The inverted rule fails open.
- **Parsed listings are enrichment, never a gate.** An `Available` observation with zero parsed
  listings must still fire a max-severity alert. A test named
  `alert_still_fires_when_no_listings_could_be_parsed` guards this.
- **A missing Ticketbörse card is never "quiet."** It raises a warning, rate-limited to once per
  24 hours.
- **`main` must exit non-zero if either task returns.** fly's restart policy is `always`, but
  returning `Ok(())` on task death previously made a dead watcher look like a clean shutdown.
- **Never edit anything under `tests/fixtures/`.** They are captured real pages and their value is
  being unaltered.
- **The `live_site` test stays `#[ignore]`d.** CI must not depend on the shop being up, and must
  not add traffic to a small shop on every push.

## 5. Constraints that are easy to violate

- **Toolchain is pinned to Rust 1.93** in `rust-toolchain.toml`. Do not change it. Do not run a
  bare `cargo update`. A transitive crate raising its MSRV has already broken this build once
  (`takecell` 0.1.2 needs rustc 1.96, which is why `takecell` is pinned to 0.1.1).
- **reqwest stays on 0.12** with the `rustls-tls` feature, to match teloxide 0.17's `^0.12.7` and
  avoid compiling reqwest twice. The rustls feature is named `rustls-tls` in 0.12 and `rustls` in
  0.13, so a naive upgrade breaks in a confusing way.
- **The runtime Docker image is `FROM scratch`** and works only because TLS roots come from
  `webpki-roots` (compiled in) and the rustls provider is `ring` (musl-friendly, unlike
  `aws-lc-rs`). Changing either silently breaks the image. The image has no shell, so
  `fly ssh console` gives no prompt; use `fly logs`.
- **`rust-toolchain.toml` must be copied into the Docker image before `rustup target add`,** or
  the musl target lands on the wrong toolchain and the build dies with `can't find crate for std`.
- **120-column lines** (`rustfmt.toml` sets `max_width = 120`).
- **Never print or echo secrets.** `.env` is gitignored and holds `TELOXIDE_TOKEN` and
  `TELEGRAM_CHAT_ID`. Nothing in the remaining tasks needs them; every test is offline. Test
  values are dummies: token `"123:ABC"`, chat id `"1"`.
- **The user's shell is fish**, not bash or zsh. `export FOO=bar` is `set -gx FOO bar`, and a
  `FOO=bar cmd` prefix does not work. Every command in the plan is a plain single command that
  works in fish as written.

### Per-task notes that are NOT in the plan

These are things I learned while running tasks 1 through 9 that the plan text does not say. They
are the failure modes most likely to cost you a cycle.

**Task 11 (tri-state main-shop detection) — ALREADY DONE in `ed59720`, kept here for
reviewers.** This was the biggest change: it renames
`PageObservation.main_sold_out: bool` to `main: MainStock` where `MainStock` is
`SoldOut | OnSale | Unknown`, and it touches six files plus three test files. The motivation:
`main_sold_out` is a *positive* matcher, so if the site renames the `turbo-frame#ticket_detail`
element, the page reads as "on sale" and fires a max-severity alert plus six reminders at 3am for
a page that has not changed. `Unknown` routes to the existing rate-limited structure warning
instead.
- Task 9 added tests that use `main_sold_out`. Task 11 step 5 lists every one of them by name.
  Missing one leaves the suite red in a way that looks like a logic error but is not.
- `apply_structure_error` gains a fourth `what: &str` parameter in this task and has two call
  sites plus four calls inside tests.
- The alert must fire on `Unknown → OnSale` as well as `SoldOut → OnSale`. That is deliberate
  fail-open behaviour, not a bug.
- `Unknown` must never produce a max-severity alert.

**Task 12 (CI).** Contains a pinned commit SHA for the flyctl action and one for the audit action.
Use the SHAs the plan gives; they were looked up against the real repositories. The new `audit`
job is deliberately NOT added to the deploy job's `needs`: a transitive advisory should not block
shipping a fix to a watcher whose downtime is the actual risk. Validate the YAML after editing.

**Task 13 (body cap).** Adds `futures-util` with `default-features = false`. See ruling 1 below:
if the build fails on a no_std path, drop `default-features = false`. Also adds the `stream`
feature to reqwest, which is what provides `Response::bytes_stream()`.

**Task 14 (truncation).** The test uses a 3000-character repetition of a two-byte character, so
naive byte slicing would panic mid-codepoint. The implementation must cut on a char boundary. The
arithmetic works out to exactly the cap, so if your assertion is off by a few bytes you have
mistranscribed the marker string.

**Task 15 (cleanups).** Removes a `fingerprint` function from `src/parse.rs` that nothing calls.
Clippy does not catch it because it is `pub`. Also removes two now-unused imports along with it.

**Task 16 (docs).** Asks you to measure the real test count and substitute it. Also adds three new
invariants to `CLAUDE.md` covering the work on this branch: bot commands only from the configured
chat, state updates pure with sending outside the lock, and "delivered" meaning at least one
channel accepted.
- **The plan predates `AGENTS.md`, so it does not mention it.** `AGENTS.md` is the guide for

## 7. Decisions already made that you should not silently undo

These were judgement calls. Each is deliberate. If you disagree, raise it with the owner rather
than quietly reverting, because a reviewer looking only at the code may reasonably flag them.

1. **`futures-util` is declared with `default-features = false`** in task 13. Cargo unifies
   features and reqwest already activates the std parts that `StreamExt::next` needs. If the build
   fails on a no_std path, dropping `default-features = false` is the fix.
2. **`MultiNotifier::send` returns success when ANY ONE channel delivered,** and an error when no
   channels exist or every configured channel failed. This is a deliberate semantic change made
   in task 9, approved by the owner. The delivery-retry logic needs a definition of "delivered",
   and the point of a second channel is that the user can see the alert somewhere. A consequence
   worth knowing: with both channels configured, a Telegram-only outage yields "delivered" and
   therefore no retry.
3. **`TELEGRAM_CHAT_ID` becomes required** unless `SB_WATCHER_DISCOVERY=1`. This supersedes the
   design document's implicit discovery mode. Approved by the owner. The intent is fail-loud: a
   blank secret becomes a startup error instead of a silently non-watching deployment.
4. **`screen.png` was moved, not deleted.** It sat unreferenced in the project root but is the
   visual source of the two detector constants, so it now lives at
   `docs/ticketboerse-empty-state.png` and is embedded in the Reconnaissance section of the design
   spec. Its `.dockerignore` entry was dropped because `docs/` is already excluded. This was
   commit `3d509c9` and was not part of the plan.
5. **`condition_state` and `reminder_body` in `src/watcher.rs` are exhaustive over `AlertKind` with
   no catch-all arm, on purpose.** The plan's text specified catch-alls; a review found that a
   future max-severity alert kind would then silently get one alert with no reminders and no
   delivery retry, with no compile error. That is exactly the fail-silently class this branch
   exists to remove, so I overrode the plan and made it a build break instead. **Do not
   "simplify" these back into a `_ =>` arm.** This was commit `45899ac`.

## 8. Final triage of the deferred findings

A review of task 9 raised four minor findings. The final whole-branch review triaged them as
follows.

1. **Open, cosmetic:** a retried reminder loses its numbering. The retry body says the previous
   alert could not be delivered but omits the "Reminder N of 6" line, while the internal counter
   has already advanced.
2. **Fixed before merge:** retries previously paused during fetch failures and cardless-page polls.
   That contradicted invariant 9 and could leave the only drop alert undelivered for an outage's
   full duration. Blind polls now retry from the last confirmed observation.
3. **Open, cosmetic:** the reminder title says "STILL AVAILABLE" even for a main-shop reminder.
   The body distinguishes the two conditions, so the alert remains actionable.
4. **Open by design:** single-channel outages are invisible to the retry path when another channel
   succeeds. This follows decision 7.2: the user receiving the alert anywhere counts as delivery.

### Verifying the alert path for real

The site cannot be made to show resale stock on demand, so the only way to prove the alert path
works before the night it matters is the fixture escape hatch:

```fish
./scripts/with-env.sh env SB_WATCHER_FIXTURE_PATH=tests/fixtures/real_available_many.html \
  POLL_INTERVAL_SECS=10 ./target/debug/sb-watcher
```

Expect ten tickets at 45,20 € — real markup from a shop that genuinely had ten on offer. Then try
`available_blob.html`, which is unrecognised markup that must still alert (the fail-open path), and
`no_card.html`, which must raise the structure warning. `scripts/with-env.sh` sources `.env` and
keeps the secrets out of shell history; use it rather than inlining any secret into a command.
